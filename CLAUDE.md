# CLAUDE.md: ferrocast-web

Read this first, every session.

## What this repo is

The web half of **Ferrocast**, the free, open-source (GPL-3.0), local-first companion app for streamers on Twitch, YouTube and Kick (never TikTok). The Rust engine lives in `../ferrocast`; this repo holds everything that runs in a browser:

| Path | What | Stack |
|---|---|---|
| `apps/dashboard` | The one dashboard: Tauri window and normal browser. Talks to the engine only over HTTP + the live WebSocket. Has a **demo mode** with an in-browser engine. | React 19, Vite, TS strict, Tailwind 4, motion |
| `apps/overlays` | The OBS browser-source bundle: one page renders an overlay's widgets. | Vanilla TypeScript, no framework |
| `apps/site` | `ferrocast.clearcraftlabs.com` (ClearCraft Labs) | Astro (static) |
| `apps/video` | Promo and feature loops rendered to WebM/MP4 into the site | Remotion |
| `packages/api` | Typed client for the engine's API, protocol parsers, TS ports of core logic, the demo engine | TS |
| `packages/ui` | Design tokens, shared React components, the ferrofluid renderer | TS, React |
| `brand/` | Logo, app icon, favicons; all generated by `brand/build.mjs` | Node |

`pnpm build` writes `dist/dashboard/` and `dist/overlays/` at the repo root. The desktop binary embeds them from `../ferrocast-web/dist`. The site builds to `apps/site/dist`.

## The contract

`../ferrocast/docs/API.md` is the source of truth. Types mirror it in `packages/api/src/types.ts`. Anything we need that API.md lacks goes into `docs/API-REQUESTS.md` (and the demo engine implements the proposal). **Never edit the engine repo.**

## Rules that matter here

- Engine rules are in `../ferrocast/docs/LESSONS.md` (R-01…R-72). Overlays: R-36…R-42. Product: R-05…R-16.
- **Viewer text is untrusted.** Overlays build DOM with `textContent` / created elements only. ESLint forbids `innerHTML` in `apps/overlays`.
- **Overlays never create events** (R-36): they send only `hello`, `ack`, `visibility`.
- **Few clicks**: every common task ≤ 3 clicks from Home.
- **Never upsell to the audience; never lead with AI** ("smart filters"). Pro is marked calmly.
- Every API error reaches the user as a plain message plus what to do (`describeError`). Never a raw exception.
- Design: `docs/DESIGN.md`. Before UI work load the `design-taste-frontend` skill; after, review with `web-design-guidelines` and check in a real browser at desktop and 375 px.

## Commands

```bash
pnpm install
pnpm dev                                   # dashboard in demo mode on :5280
pnpm --filter @ferrocast/overlays dev      # overlay page with ?demo on :5290
pnpm --filter @ferrocast/site dev          # website on :5300
pnpm build                                 # dist/dashboard, dist/overlays, apps/site/dist
tools/check.sh                             # every gate (tools/check.sh --fast skips browsers)
pnpm --filter @ferrocast/brand build       # regenerate logo, icon, favicons
pnpm --filter @ferrocast/video render      # render the promo loops into the site
```
